# UI

Brand placeholder: **Campus Accessories**. The UI redesign uses a warm, editorial campus-tech system: Warm Cream `#F7F1E7` is the environment, Soft Ivory `#FFFDF8` is the elevated surface, Espresso `#5A3825` is the primary action/brand color (Deep Coffee `#432719` hover), and Dark Cocoa `#2C211B` is the main text. Warm Taupe `#806F63` supports metadata, Warm Sand `#E5D8C8` provides borders, and Caramel `#B98255` is an occasional decorative highlight. Forest `#3F6249` and Brick `#9B4A3C` provide success/error meaning. These values are centralized in `app/globals.css`; lime is not part of the visual system.

Typography uses an editorial serif display face (Georgia fallback) for major headings and a modern system sans stack for reading, labels, and controls. Spacing uses compact control spacing with `clamp()` section rhythm; radius steps are small controls, medium inputs, large cards, and extra-large feature surfaces. Borders and low-opacity warm shadows separate surfaces without making every element float. Dark mode is intentionally not implemented: the warm paper/espresso system is the deliberate, accessible product identity.

Use accessible labels, visible focus states, keyboard-operable controls, sufficient contrast, and semantic headings. Customer navigation is Home, Shop, and Cart. Desktop/tablet show primary navigation; mobile shows the cart and an accessible disclosure menu, while the hamburger is CSS-hidden from `md` upward. Homepage featured products and all shop results use the same compact two-column grid at every breakpoint. `/shop` has a responsive search/category/sort form and URL-backed reset state. Product cards clearly show category, database price, availability, and a view-product link. `/shop/[slug]` adds an accessible variant and quantity chooser with stock-limited add-to-cart feedback. `/cart` and `/checkout` use calm, mobile-safe summary cards; checkout clearly stops at a server-verified “Ready for payment” review and does not imply a completed purchase. Lucide icons are used for interface symbols; `next/image` is used for configured Supabase Storage assets, with an accessible fallback for missing images.

Protected administration uses the same visual language, with compact mobile-safe controls. `/admin/products` presents search/filter controls and responsive product records showing primary-image fallback, price, summed active-variant stock, low/out-of-stock state, status, featured state, update date, edit, and archive/restore actions. Create/edit forms group product information and variants; prices are explicitly entered in integer kobo to avoid misleading floating-point handling. `/admin/categories` supports creation, inline editing, product counts, and archive controls. The product editor has a lightweight storefront link and image gallery/upload section; the first image is the primary image. Forms expose accessible labels, visible focus, pending/disabled states, inline validation, and generic safe error messages.

`components/ui/motion.tsx` defines the GSAP easing/duration tokens and a `Reveal` wrapper using `ScrollTrigger` with one-time, soft opacity/vertical reveals and optional child stagger. `PageTransition` uses a short path-change reveal without delaying navigation. Both use `gsap.context()` cleanup and disable non-essential animation under `prefers-reduced-motion`; content is never initially hidden in that mode. The mobile header uses an accessible compact menu, while desktop keeps primary discovery and contact actions visible.

The storefront refinement keeps the warm system but tightens hero, section, filter, card, and footer spacing so product content appears earlier without removing hierarchy. It makes no catalogue, cart, checkout, payment, order, or authentication change. See `docs/phases/UI-STOREFRONT-REFINEMENT.md`.
